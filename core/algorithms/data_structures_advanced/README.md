# Data Structures Advanced — Kotlin

Implementación de la especificación [07_Data_Structures_Advanced](../../../../docs/core/algorithms/07_Data_Structures_Advanced.md) en **Kotlin**, con un enfoque manual y minimalista.

**ES:** Se implementan un árbol binario de búsqueda (`BinaryTree`) y un grafo dirigido (`Graph`) a partir de la clase base abstracta `Node` y sus derivaciones `TreeNode` y `GraphNode`. El registro de vértices se construye manualmente mediante una lista enlazada canónica de nodos sin delegar en tablas hash ni diccionarios. El proyecto usa Gradle con el plugin de Kotlin JVM y Kotest sobre JUnit Platform para las pruebas.

**EN:** A binary search tree (`BinaryTree`) and a directed graph (`Graph`) are implemented from the abstract base class `Node` and its derivations `TreeNode` and `GraphNode`. The vertex registry is manually constructed through a canonical linked list of nodes without delegating to hash tables or dictionaries. The project uses Gradle with the Kotlin JVM plugin and Kotest over the JUnit Platform for tests.

| `Node.value` | `→ Int` | `O(1)` | Propiedad inmutable que expone el valor del nodo / Immutable property exposing node value |

## 🧩 Decisiones de diseño / Design decisions

| Decisión / Decision | Alternativa considerada / Alternative | Razón / Reason |
|---|---|---|
| `abstract class Node(val value: Int)` como base con herencia directa en `TreeNode` y `GraphNode` | Composición con valor embebido en cada nodo | Kotlin ofrece herencia directa y concisa; la clase abstracta impide instanciar la base directamente y centraliza `val value` de forma segura / Kotlin provides direct, concise inheritance; an abstract class prevents direct base instantiation and centralises `val value` safely |
| Registro enlazado canónico de vértices (`nextVertex: GraphNode?`) en lugar de `Map` o `Set` | Usar `HashMap<Int, GraphNode>` o `HashSet` | La especificación prohíbe delegar el registro de vértices en mapas, tablas hash o colecciones indexadas; se implementa una lista enlazada canónica explícita con recorrido manual `O(V)` / Specification forbids delegating vertex registry to maps, hash tables or indexed collections; an explicit canonical linked list with manual `O(V)` traversal is implemented |
| `MutableList<Int>` con inserción ordenada manual para vecinos de `GraphNode` | Estructura enlazada propia `NeighborNode` o `TreeSet` | La especificación autoriza expresamente una lista estándar para el almacenamiento de vecinos, siempre que la búsqueda, inserción ordenada y control de duplicados se programen manualmente / Specification explicitly allows standard list for neighbour storage, provided search, sorted insertion and duplicate checks are coded manually |
| Copia inmutable `toList()` en `Graph.getNeighbors` | Retornar la lista mutable interna o una vista delegada | Garantiza el aislamiento total del resultado frente a modificaciones externas posteriores o llamadas adicionales a `addEdge`, cumpliendo el contrato de inmutabilidad / Ensures full isolation of the returned sequence against subsequent external mutations or later `addEdge` calls, satisfying the immutability contract |
| Pruebas con Kotest `StringSpec` y función auxiliar `step` | JUnit 5 estándar con `@Test` | Alineado con la base `numbers`, Kotest ofrece descripciones expresivas por paso con contexto de fallo detallado (`withClue`) / Aligned with the `numbers` base, Kotest provides expressive step descriptions with detailed failure context (`withClue`) |

## 📝 Notas de implementación / Implementation Notes

**ES:**
- **Recursión e iteración:** Todas las operaciones de búsqueda e inserción en `BinaryTree` y `Graph` se implementan de forma iterativa mediante bucles `while`, evitando el desbordamiento de pila en árboles profundos o grafos extensos sin depender de optimización de cola (`tailrec`).
- **Manejo de ausencia y errores:** Se aprovecha el sistema de tipos de Kotlin con tipos anulables (`TreeNode?`, `GraphNode?`, `List<Int>?`). El valor `null` representa enlaces ausentes o vértices no encontrados en `getNeighbors(u)`, distinguiéndose inequívocamente de la lista vacía (`emptyList()`) devuelta para vértices aislados.
- **Aislamiento y almacenamiento:** `GraphNode` almacena sus vecinos en una lista mutable ordenada de enteros (`MutableList<Int>`). `Graph.getNeighbors` retorna una copia independiente (`toList()`), previniendo efectos colaterales de mutación externa sobre el estado interno del grafo.
- **Registro canónico de vértices:** El registro de vértices se construye manualmente mediante la referencia `nextVertex` enlazando instancias de `GraphNode`, satisfaciendo la prohibición expresa de recurrir a mapas, tablas hash o diccionarios estándar.
- **Organización de tests:** Las pruebas utilizan Kotest con el estilo `StringSpec`. La función `step` envuelve las aserciones con `withClue` para proveer mensajes de diagnóstico claros en caso de fallo.

**EN:**
- **Recursion and iteration:** All search and insertion operations in `BinaryTree` and `Graph` are implemented iteratively using `while` loops, avoiding stack overflow on deep trees or large graphs without relying on tail-call optimisation (`tailrec`).
- **Absence and error handling:** Kotlin's type system is leveraged with nullable types (`TreeNode?`, `GraphNode?`, `List<Int>?`). The `null` value represents absent links or vertices not found in `getNeighbors(u)`, cleanly distinguished from the empty list (`emptyList()`) returned for isolated vertices.
- **Isolation and storage:** `GraphNode` stores neighbours in a sorted mutable integer list (`MutableList<Int>`). `Graph.getNeighbors` returns an independent copy (`toList()`), preventing external mutation side effects on the graph's internal state.
- **Canonical vertex registry:** The vertex registry is manually constructed using the `nextVertex` pointer linking `GraphNode` instances, satisfying the explicit prohibition against relying on standard maps, hash tables or dictionaries.
- **Test organisation:** Tests use Kotest with the `StringSpec` style. The `step` helper wraps assertions in `withClue` to provide clear diagnostic failure messages.
